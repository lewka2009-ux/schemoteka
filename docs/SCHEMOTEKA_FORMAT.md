# Схемотека: формат проекта (для Claude / разработчика CRM)

Версия документа: 24.11.2026, приложение TH v147. Автор формата — Алексей Силюк (SmartSec PRO / ИП Силюк).
Документ для чтения кода и данных Схемотеки из CRM и бота техподдержки. Схемотеку из CRM **только читаем**. Изменения в приложении вносит Алексей.

---

## 0. Главное за 30 секунд

- Схемотека — одностраничное веб-приложение: один HTML примерно на 1,1 МБ, весь JS внутри. Проект — это один JSON-объект `P`.
- **Главная версия** — артефакт Claude у Алексея. Копия на GitHub Pages / Google Диске — только сборка для сотрудников. Её не правят: она скачивает обновления из главной.
- Версии отличаются полем `region`:
  - `'th'` — SmartSec PRO, Таиланд, ฿, листы и КП на английском, VAT 7 %, WHT 3 %;
  - `'ru'` — ИП Силюк, ₽, без НДС.
  
  Проект чужой версии не открывается.
- **Итоги сметы в проекте не хранятся.** Сумма пересчитывается из устройств, линий и трасс с учётом правок в `P.est` (см. §6). Сумму для CRM брать из выгрузки (КП PDF / BOQ xlsx) или пересчитывать самим приложением.
- **Клиент** (с v147): `P.client` — необязательный блок с `crmId`. Это единственное поле, которое CRM может считать ключом связи (см. §3).
- Обратная совместимость: новые поля только добавляются, существующие не переименовываются и не удаляются. Неизвестные поля приложение сохраняет как есть.

## 1. Где лежат проекты

| Хранилище | Что там | Как читать |
|---|---|---|
| База артефакта (основная) | коллекция `data/users/me`: 1 документ = 1 проект, `doc_id = P.id` | инструмент ArtifactData (Claude) |
| Google Диск, облачная версия | `Схемотека/05 Данные/…` (через Apps Script `Code.gs`) | API Apps Script, `op:'get'/'list'` с ключом |
| Google Диск, файлы объектов | `Схемотека/01 Проекты/<Объект>/<Объект>.json` — ежедневная выгрузка, плоский JSON | читать файл |
| Полная копия | `Схемотека/02 Резервные копии/Схемотека-полная-копия-ГГГГ-ММ-ДД.json` = `{app, version, exportedAt, projects:[P,…]}` | читать файл |
| Экспорт из приложения («Копии → скачать») | тот же формат `{app, version, exportedAt, projects:[…]}` | — |

**Сжатые записи в базе.** Если JSON проекта занимает ≥150 000 символов, запись выглядит так:
`{id, name, system, region, updatedAt, nFloors, nNodes, _gz:1, gz:"<base64 gzip JSON>"}`.
Если base64 длиннее 240 000 символов, вместо `gz` стоит `gzn:n`, а куски лежат в `data/users/me/pparts/items`: документы `<id>_0 … <id>_{n-1}`, склеивать поле `d`.
Распаковка: `gzip.decompress(b64decode(gz))`. Файлы на Диске (`01 Проекты`, полные копии) уже распакованы.

**Подложки** (планы-картинки) в проекте не хранятся. В проекте лежит ссылка на файл ассета, `floors[i].underlay.asset`; в старых проектах — куски в `ublobs/items`. Для CRM подложки не нужны.

## 2. Верхний уровень `P`

```jsonc
{
  "id": "lux7v01",            // 7 символов [a-z0-9], ключ проекта
  "name": "The Lux 7 Villa, Phuket",
  "region": "th",             // 'th' | 'ru' (нет поля — открывается везде)
  "system": "cctv",           // основной раздел: cctv | smart | acs | lan | elec | audio
  "updatedAt": 1795162981852, // мс, Unix; используется для синхронизации («побеждает новее»)
  "scale": 1.1686,            // см на 1 px плана: метры = px * scale / 100
  "floors": [ {"id":"f1","name":"Этаж 1","h":3,"underlay":{"asset":"…","w":…,"h":…}} ],
  "floor": "f1",              // текущий этаж в интерфейсе
  "nodes": [ … ],             // устройства (§4)
  "edges": [ … ],             // линии / кабели между устройствами (§5)
  "walls": [ … ],             // стены, двери, окна, трассы (лотки, трубы), стояки (§5)
  "zones": [ … ],             // помещения / зоны
  "est": { … },               // параметры и ручные правки сметы (§6)
  "sheet": { … },             // штамп листов и шапка КП (§3)
  "client": { … },            // карточка клиента для CRM, v147+ (§3), необязательно
  "legend": {}, "legendExtra": [], "frames": {}, "sheetAdj": {}, "arch": {},   // оформление листов
  "form": {"zones": []},      // мастер «Форма»
  "tr": {}                    // ручной перевод строк на английский (th)
  // прочие служебные флаги интерфейса: viewMode, topoView, showCables, dropV, reserve, rackPosV, lastSnap …
}
```

## 3. Клиент и шапка документов

### `P.sheet` — штамп и шапка КП (есть во всех версиях)

| Поле | Смысл |
|---|---|
| `client` | Заказчик: название в штампе и в блоке «TO» в КП |
| `clientAddr` | Адрес объекта / заказчика (печатается в штампе и в КП) |
| `projectNo` | Номер проекта, например `5-CCTV/09/26` |
| `subtitle` | Подзаголовок (системы) |
| `company`, `companyAddr` | Исполнитель (по умолчанию SMART SEC PRO / ИП Силюк) |
| `drawnBy`, `checkedBy`, `approvedBy`, `date`, `rev`, `size` (A3/A2) | Поля штампа |

### `P.client` — карточка клиента (v147+, необязательно)

```jsonc
"client": {
  "crmId":   "CL-0042",                   // ID клиента в CRM — КЛЮЧ СВЯЗИ
  "name":    "Synergy Nexus Co., Ltd.",   // всегда = P.sheet.client
  "taxId":   "0835569004249",             // Tax ID / ИНН
  "addr":    "…",                         // юр. адрес клиента; если задан — идёт в КП вместо sheet.clientAddr
  "contact": "Mr. Vladimir Ianchev, Managing Director",
  "phone":   "+66 …",
  "email":   "…"
}
```

Правила:
- Пустые поля не хранятся. Блока может не быть совсем: старые проекты, клиент не указан.
- При открытии старого проекта, у которого заполнен `sheet.client`, приложение создаёт `client = {name: sheet.client}`. В базу это попадёт при следующем сохранении.
- `client.name` и `sheet.client` синхронизирует приложение: правка одного меняет другое.
- В интерфейсе поля находятся на вкладке «Листы / PDF», раздел «Клиент — карточка для CRM».
- Привязка из CRM: по `client.crmId`. Если `crmId` нет — предложить пользователю сопоставить по `client.name` / `sheet.client`. Название проекта `P.name` для связи не использовать.
- Номер проекта для CRM — `sheet.projectNo`, ID проекта — `P.id`.

## 4. Устройства `nodes[]`

```jsonc
{"id":"sfvehj5","type":"dome","floor":"f1","x":134.8,"y":277.1,"label":"CAM11",
 "cam":{"dir":-7,"h":3,"lens":4,"mp":4},   // камеры: направление°, высота м, объектив мм, Мп
 "parent":"r9it3zd",                       // устройство внутри шкафа (id шкафа)
 "units":1, "rackPos":8,                   // высота в U и позиция в шкафу
 "zone":"…", "mdl":{…}, "exist":true, "note":"…", "acp":"…", "lp":{"dx":…,"dy":…}}
```

- `x`, `y` — px на плане этажа `floor`. `label` — обозначение на плане (CAM1, AP3, SW1…).
- `exist:true` — существующее оборудование: на плане бледное, в смету не входит.
- `mdl` — своя модель или цена для конкретного устройства, перекрывает каталог.
- `parent` — шкаф, в который установлено устройство. Шкаф — устройство с `type:'rack'`.

Типы `type` по разделам:
- **cctv**: rack, nvr, poesw, sw, ups, patch, fodf, org, router, monitor, dome, bullet, ptz, ap, outlet, fout, jbox
- **lan**: rack, sw, poesw, patch, router, ups, ap, outlet, fout, jbox
- **smart**: hub, router, motion, contact, leak, smoke, relay, swall, thermo, bulb, shpanel, slock, curtain, lc, psu24, zcb, thsensor, gatectl, doorbell
- **acs**: ctrl, psu, reader, lock, exit, turn, barrier, dsens (точки контроля: `acp`)
- **elec**: panel, meter, breaker, rcd, socket, swall, lamp, osocket, dimmer, downlight, wlamp, olamp, track, ledstrip, ledpsu, daligw, fan, appl, jbox
- **audio**: rack, mamp, strm, ashelf, amp, spk, spkw, sub, hdmi, swall

Устройства всех разделов лежат в одном массиве. Раздел определяется по типу; общие типы вроде rack и swall относятся к нескольким разделам.

## 5. Линии, трассы, стены

**`edges[]`** — связь двух устройств:
`{"id","a":nodeId,"b":nodeId,"cable":"UTP cat6","code":"B6","port":{"id":patchId,"n":6},"tray":"auto","pts":[…],"len":…,"wireless":false,"exist":false}`
- `code` — номер линии в кабельном журнале: B — видео, C — СКУД, K — сеть, и т. д.
- `tray` — прокладка: `'auto'` — по ближайшей трассе.
- `pts` — ручная траектория. `len` — ручная длина, м.
- `wireless:true` — радиосвязь (Zigbee, Wi-Fi), кабеля нет.
- Длину кабеля считает приложение: трасса, плюс подъёмы, плюс запас.

**`walls[]`** — геометрия на плане, `pts:[{x,y},…]`, `floor`:
- `kind:'wall'|'vwall'|'door'|'window'` — архитектура.
- `kind:'tray'`, `sub:'pipe'|'gofra'|'kanal'|'lotok'` — трасса: труба ПВХ, гофра, кабель-канал, лоток. `size` — сечение, мм.
- `kind:'riser'` — межэтажный переход, `vsub`/`vsize`.

**`zones[]`** — помещения: прямоугольник `x,y,w,h` + имя. Устройство ссылается на зону полем `node.zone`.

## 6. Смета (`P.est`) — как считается

`P.est` хранит **параметры и ручные правки**, а не итоги:

```jsonc
"est": {
  "curr":"฿", "vat":7, "wht":3, "tax":0,
  "rates":{"exec":350,"com":1400,"cexec":800,"ccom":1600,"dexec":500,"dcom":2000}, // ставки ч: исполнитель / в КП (монтаж, ПНР, проект)
  "logW":0, "logM":1000, "logD":1000,          // логистика (себестоимость)
  "dev": {"<ключ>":{"model","buy","sell"}},     // правки оборудования; камеры: "type|Мп|объектив"
  "mat": {"<ключ>":{"buy","sell"}},             // правки материалов (tray_pipe_25, p_patch, fit, jb…)
  "works": {"<ключ>":{…}},                      // правки нормативов
  "extraDev":[], "extraMat":[], "extraWork":[]  // строки, добавленные вручную
}
```

Расчёт (`estSummary()` в коде):
- **работы** = Σ(часы × ставка КП). Часы = количество × норматив из матрицы Схемотеки.
- **материалы** = Σ(кол-во × sell). Кабель — по кабельному журналу, трубы и лотки — по трассам.
- **оборудование** = Σ(кол-во × sell).
- `sub` = работы + материалы + оборудование.
- `vat` = sub × 7 %. `wht` = работы × 3 %. Итог к оплате = sub + vat − wht.

Цены и каталог в публичной сборке GitHub вынесены в `private.json` на Диске и подгружаются по ключу. **В CRM и в публичный код цены не копировать.**

Итог для CRM надёжнее всего брать из выгрузок проекта (КП PDF, BOQ xlsx, лист Quotation). Если понадобится итог прямо в JSON — это отдельная доработка: например, поле `P.summary {sub,vat,wht,total,hours,at}`, обновляемое при сохранении. Запрашивать её у Алексея.

## 7. Правила для кода CRM / бота

1. Схемотеку только читать. Писать в проекты нельзя: при одновременном сохранении правки потеряются.
2. Неизвестные поля игнорировать, а не падать. Поля могут появляться в новых версиях.
3. Проверять `region`: тайская и российская версии не смешиваются.
4. Распаковывать `_gz` и `gzn` (§1).
5. Связь с клиентом — по `client.crmId`. Связь с проектом — по `P.id`.
6. Нужно новое поле или изменение — написать Алексею. Изменения делаются в главной версии и приходят в копию обновлением.
